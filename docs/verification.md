- DOM 测试覆盖上下文匹配、用户内容保护、动态菜单、节点复用、属性变化、隐藏/受保护区域、原文恢复、重复切换、脱离文档后重新插入的节点，以及资料库子页。

- 队列稳定后不再增加处理批次或写入次数；切换开关后不重复注册监听；保留原有 DOM 元素和点击处理器。

## 浏览器可视化结果

浏览器操作由 `ui_verifier` 执行；协作配置指定 `gpt-6-sol`，工具没有独立查询实际模型标识的接口。

本地合成页通过普通 script 标签加载与安装文件相同的构建产物，模拟油猴设置与菜单。已观察到：

- 中文导航、创作模式、歌词/风格标题、高级选项显示正常。
- 歌词编辑区的 `Create`、风格输入的 `Styles`、歌曲标题的 `Create` 保持原文。
- 中英文切换后界面恢复；分别刷新英文和中文状态，偏好保留。
- 从创作页导航至资料库后，标签和筛选入口正确汉化。
- 动态打开筛选和歌曲菜单时，可见“公开/私密/隐藏分轨/分享/下载”；弹层展开时切换语言正常。
- 未观察到本地页面来源的控制台 error/warn。浏览器其他扩展有警告，未归因于本项目。

可复现方式：`npm run build`，然后 `npm run preview`，访问 `http://127.0.0.1:4319/create`。测试页面无真实账户数据。

## 未完成的验证

当前浏览器工具拒绝访问 Chrome 扩展管理页，且页面脚本求值仅允许只读；没有获准的本地脚本注入接口。因此没有安装或向真实 Suno 注入脚本，不声称真实 Suno 汉化验收通过。

安装后仍需检查：真实创作模式切换和文字输入、实际页面内导航、不同套餐/布局、其他 Library 子页与弹窗、真实 DOM 更新时的兼容性与性能。没有通过生成歌曲来测试，以免消耗额度。

`aria-label` 为避免改变定位和交互依据暂不翻译；屏幕阅读器可能继续读出英文。字体和复杂弹层布局仅在合成页检查过。Suno 改版或无法识别的文案会保留英文。

## 安装后的人工验收步骤

1. 安装构建脚本，刷新真实 Suno 的 Create 和 Library 页面。
2. 在空白草稿中检查 Simple / Advanced / Sounds、More Options 展开与编辑输入，确认内容不被替换；无需点击 Create。
3. 检查导航往返、Library 筛选和歌曲菜单，不执行分享、下载、删除等动作。
4. 切回英文并刷新，再切中文并刷新，确认页面文字和偏好一致。
5. 若出现遗漏或行为异常，先通过油猴菜单切回英文，记录固定文案及界面位置；不提交个人内容截图。
